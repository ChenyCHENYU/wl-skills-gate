## 执行入口与闭环责任

项目钩子与 CI 自动触发是主要执行入口；开发者不额外输入质量检查命令。确认后的机械修复与反馈由包内生成的项目动作调用同包fix引擎，业务/安全判断保留独立 Review。完整闭环还有已接项目准入与治理监督：

| 层 | 完成条件 |
|---|---|
| 项目 | 固定执行器/锁/受管资产，正确根目录，统一命令，轻量 Hook，检查不改源码 |
| 流水线 | 按批准工作副本清单/锁准备环境，关闭任意生命周期；对真实 SHA 检查/测试；构建前正式 Review 与当前 CI 重验；失败留原件并阻断 |
| 统一质量服务 | 共享分支保护、真实候选、九维独立授权/签发；组合与部署重验当前 Review、实际制品和对应动作授权 |
| 治理 | 可信事件、幂等主台账、主备/复核、认证跳转、可靠待发箱、SLA/对账、独立关闭 |

“共享实现已验证”“业务项目已接入”“已接项目准入已验收”“业务问题已关闭”分别登记。模拟和隔离验证不能代替真实接线证据。

## 后端检查的准确定位

需要的 CodeCC 相关精选检查已纳入 BD Maven 规则/复核指引与 Gate Java 风险分级，属于可进入正式链的检测能力。Gate 保留引擎身份、成员、原生等级与定位，确定缺陷阻断、待上下文判断风险留 warning。详见 [15 Java 风险](15-java-report-triage.md)。

原始 code-scan-kit 是另一套确定性编排，本轮补其失败关闭、范围/新鲜度和报告契约。是否选为某维度生产者由批准适用表决定，不能把整套已集成能力概括为“仅辅助审计”。同一维度选一个正式生产者，不默认重复运行两套 PMD/Checkstyle/SpotBugs；CPD/CCN 无共享适配的部分单独批准消费方案。

BD 的 verify:quality-codecc 等属于源码包维护者夹具验证。业务项目执行自己的 POM、源码和真实测试。PMD 7 与 P3C/PMD 6 分开调用和保存输出。

## 共享入口与资产

| 资产 | 使用位置与边界 |
|---|---|
| setup project / workspace | 首次接入编排差异确认、固定安装、规则/POM/锁与 Hook 首扫；新克隆按已提交清单恢复，不重写策略 |
| 九维Review | 自动草稿、非作者逐维授权、独立签发；构建按 SHA 自动选择当前正式版本并重查 CI，组合/部署再验原件 |
| collect-ci与分类卡片 | 真实GitLab/Jenkins API与原始工件、构建/Review事实、同源卡片/待发箱，默认不真实发送 |
| doctor | 只读盘点前后端的依赖/资产/策略/POM 准备度，不执行项目测试或安装；CI/Jenkins 作业另由统一质量服务核验 |
| JUnit 多报告与共享 producer | 显式 files/reportDirs/requiredSuites/requiredTests，真实同轮生产，全量 XML 与 testcase 校验 |
| [Java 单元生产器](../templates/scripts-quality/java-unit.mjs) | 依批准 plan 准备依赖，再在真实测试模块运行 unit，不把跳测准备当测试 |
| [CI 接入](07-jenkins.md) | Jenkins安装服务器公共入口，由fleet批量配置；[GitLab模板](../templates/ci/)按其实际候选检查与权限要求接线 |
| [治理模板](../templates/platform/) | 独立统一质量服务签名 receipt、幂等台账、动作校验、待发箱、预览/显式发送、自然分钟 SLA/预期运行对账 |

包内collect-ci提供固定GitLab/Jenkins只读查询；实际来源配置、SSO、认证网页、应用回调、工作日历和企业群权限由团队现有环境配置。receipt 签名要求统一质量服务先核验真实来源/身份。首期 SLA 为中央首次摄入起的自然分钟，源发生/接收延迟单独观测，不冒充完整工作日历。共享首期采用中央串行台账及写锁；多实例/数据库/外部系统需保留相同幂等与审计语义的适配。

共享版本与项目已装版本、registry 发布状态分别核验。组合工具当前至少 Node 22，正式固定符合项目要求的 Node 22.13+或24+、pnpm/JDK/Maven、settings/toolchains 和镜像摘要。Gate 升级引入新 schema/能力时，同步审查 policy、工具锁、基线和批准摘要。
